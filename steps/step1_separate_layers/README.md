# Step 1: 関心の分離 (レイヤー分割)

Step 0 の「モノリス（密結合）」状態から一歩進め、**関心の分離 (Separation of Concerns)** に基づいてシステムを複数のレイヤー（層）に分割しました。

ここでは、単純な「3層アーキテクチャ (UI / Service / Data Access)」を採用しています。

## 構成とコードの解説

各ファイルは明確な役割（責務）を持っています。

- **`src/cli.py` (プレゼンテーション層)**
  - ユーザーインターフェース (UI) を担当します。
  - ユーザーからの入力 (`input()`) を受け取り、結果を画面 (`print()`) に出力します。
  - ビジネスロジックそのものは持たず、必要な処理はすべて `service.py` に委譲します。
- **`src/service.py` (サービス/ビジネスロジック層)**
  - アプリケーションの「やりたいこと（ビジネスルール）」を担当します。
  - 在庫のチェックや合計金額の計算などを行います。
  - データの取得・更新は `data_access.py` を呼び出して行い、結果を `cli.py` に返します。
- **`src/data_access.py` (データアクセス層)**
  - データ（商品、カート、注文）の保存と取得を担当します。
  - 現在はインメモリの辞書（グローバル変数）でデータを管理していますが、将来的にこれをデータベースに置き換える役割を担います。
- **`src/main.py`**
  - アプリケーションの単なるエントリーポイント（起動口）です。

## 前回 (Step 0) からの改善点

レイヤーごとにファイルを分割したことで、以下のようなメリットが生まれました。

1. **変更時の影響範囲が明確になった**
   Step 0 では1つのファイルに全機能が混ざっていましたが、今回は「見た目を変えたいなら `cli.py`」「計算ルールを変えたいなら `service.py`」と、直すべき場所がすぐにわかります。
2. **影響が独立し、壊れにくくなった**
   UI の変更がビジネスロジックに影響を与えたり、その逆が起きたりしにくくなりました。「1箇所変えたら関係ないはずの機能まで全部壊れた」というモノリス特有の事故が起きにくくなります。
3. **テストがしやすくなった**
   「ユーザー入力と画面出力」を伴わない `service.py` 単体のテストが可能になりました。各ビジネスロジックごとにテストができるため、どの機能まで動作保証できているかが非常にわかりやすくなっています。
4. **別のUI（Web APIなど）への拡張が容易になった**
   ビジネスロジックが `service.py` に独立しているため、将来もし「CLIではなくWebアプリ (FastAPIなど) にしたい」となった場合でも、`service.py` は一切変更せずに再利用できます。

## 現時点での問題点 (Step 2 へ向けて)

一見きれいになったように見えますが、まだ Clean Architecture に至るにはいくつかの課題が残っています。

1. **データアクセスへの「強い依存 (密結合)」**
   `service.py` は `data_access.py` を直接 `import` して使用しています。もし「インメモリから MySQL に変えたい」となった場合、`service.py` のコードまで修正が必要になる可能性があります（ビジネスロジックがインフラの詳細に依存している）。
2. **ドメインモデルの不在（辞書の引き回し）**
   現在、商品や注文のデータは単なる「辞書 (`dict`)」として各層を行き来しています。キーのタイポ（例: `product['stok']`）などによるエラーが実行時まで気付けず、また「カートの合計金額を計算する」といったドメイン特有の知識が `service.py` に手続き的に書かれています。
3. **テストにおけるグローバル状態の問題**
   `test_service.py` のテストを実行する際、依然として `data_access.py` のインメモリデータ（グローバル状態）に書き込みを行っています。そのため、テストごとに `conftest.py` で状態を初期化しなければならず、並列テストなどが難しい状態です。

---

次の **Step 2** 以降では、これらの問題を解決するために **「ドメインモデルの導入」** や **「リポジトリパターンの導入」** を行い、ビジネスロジックをより堅牢にしていきます。
